# AI 활용 생산성 향상 PoC 포털

SK hynix × SK AX — 선정된 과제의 요구사항을 **SDLC 단계별 기준 공수**와 **실제 투입 공수**(AI 도구 내 + AI 도구 외)로 비교하는 포털입니다.
과제 선정은 포털 밖에서 끝나고, 관리자가 선정 결과(기준정보 엑셀 '생산성 측정 PoC 데이터')를 올립니다.

## 바로 실행

### 외부망 / 로컬 시연 (DB 없이)

```bash
npm install
npm run local        # 빌드 후 실행 — http://localhost:5176 (사내 공유: http://<내 IP>:5176)
```

- **사내 PC 시연은 `npm run local` 을 쓰세요.** (dev 서버와 동시에 빌드하면 `.next` 를 서로 덮어씁니다. 함께 띄워야 하면 `NEXT_DIST_DIR=.next-local npm run local`) `npm run dev` 는 화면을 처음 열 때마다 컴파일해서 백신이 도는 PC 에서 수 초~수십 초씩 걸립니다. 코드를 고칠 때만 `npm run dev`.
- `config.yml` 이 없으면 `data/` 폴더의 JSON 파일에 저장하고, 샘플 과제 10건·요구사항 34건(4건은 최근 10일 공수까지, 6건은 측정 전)·데모 계정이 들어갑니다. 로그인 화면 아래 데모 계정을 누르면 입력됩니다.

| ID | 역할 | 비밀번호 |
|---|---|---|
| admin | 관리자 | admin123! |
| dev01 ~ dev06 | 개발자 (김개발·박개발·최개발·이개발·정개발·한개발) | demo1234! |
| view01 | 열람자 (SK hynix) | demo1234! |

데모 데이터를 처음 상태로 되돌리려면 서버를 끄고 `data/` 폴더를 지운 뒤 다시 실행합니다.

### 사내망 (Oracle)

```bash
cp config.example.yml config.yml   # db 3개 값 입력
npm install
npm run local
```

- 접속 계정에 `POC_` 테이블이 없으면 **처음 연결할 때 자동으로 생성**합니다. DBA 가 직접 만들어야 하면 `sql/create_tables.sql` 을 실행하세요.
- 2026-10-15 개편으로 `POC_PRJ_MAS`·`POC_MEAS_DAT` 구조가 바뀌었습니다. 이전 버전 테이블이 있으면 지우고 다시 만드세요(파일 끝 ROLLBACK 주석).
- 계정 테이블이 비어 있으면 `admin` / `admin123!` 1건을 만듭니다. 데모 계정·샘플 과제는 Oracle 에는 들어가지 않습니다.
- 운영에서는 `config.yml` 의 `auth.secret`(또는 환경변수 `AUTH_SECRET`)을 꼭 넣으세요. HTTPS 면 `AUTH_COOKIE_SECURE=true`.

### 사내 서버 배포 (`deploy.sh`)

```bash
# 최초 1회 — deploy.sh 위쪽 [설정](GIT_REPO_URL·브랜치·DEPLOY_DIR) 을 고친 뒤
mkdir -p /home/idms/devopspilot && cp deploy.sh /home/idms/devopspilot/
cd /home/idms/devopspilot && ./deploy.sh prd        # 첫 실행은 config.yml 이 없어 멈춤
cp config.example.yml config.yml && vi config.yml   # db·auth.secret·collect.token
./deploy.sh prd                                     # 이후 배포는 이것만 (dev: ./deploy.sh dev)
```

- 순서: git fetch·reset → config.yml 확인 → 서버 중지 → `npm install` → `.next` 비우고 빌드 → devDeps 정리 → `next start -p 5176` (nohup, `app.pid`·`app.log`, 배포 기록 `deploy.log`).
- `config.yml`·`data/` 는 git 에 없어서 배포해도 그대로 남습니다. prd 는 `config.yml` 이 없으면 배포를 멈춥니다(데모 데이터로 뜨지 않게).

## 기준정보 엑셀 → 포털

과제 선정 관리 화면의 **엑셀 내려받기**가 현재 데이터를 담은 양식입니다. 같은 파일을 고쳐 **엑셀 올리기**로 반영합니다.

| 시트 | 포털 |
|---|---|
| 01. 과제 | 과제 ID(예 `DAE01`, 영문·숫자 — 공수 태그 앞자리) 와 과제 정보 |
| 02. 요구사항-SDLC | 한 행 = 요구사항 × 단계. **공수 태그** `과제ID-요구사항ID-단계`(예 `DAE01-REQ0047-DV`). 난이도·필요 등급·기준 공수·공수 출처·측정 상태(완료)·완료일·적합도 평가는 단계마다 |
| 03. 공수 태그 매핑 | 공수 태그 → 담당 사번 한 명 · 개발자 권한 관리(사번 = 로그인 ID, 본부·팀, 권한, **AI 도구 계정**) |
| 04. 기준정보 | 인건비 단가(원/MM 참고, 원/MD 로 계산) · 토큰 단가(모델별 입력·캐시 입력·출력 원/100만 토큰) |
| 05. 주요 집계 로직 | 읽지 않음 — 포털 `measure/metrics.ts` 의 지표 정의를 내보냄 |

- 파일에 있는 행은 파일 값으로 고치고, 없는 행은 그대로 둡니다(삭제는 화면에서). 요구사항 ID 는 과제 안에서만 겹치지 않으면 됩니다.
- 새 사번은 계정을 만들고 초기 비밀번호를 결과 창에 한 번만 보여 줍니다.
- 오류가 하나라도 있으면 아무것도 저장하지 않고 시트·행·이유를 보여 줍니다.

## Codex 사용 시간 수집

세션의 **브랜치명·프롬프트에 공수 태그**(예: `DAE01-REQ0047-DV`, 공수 입력 화면에서 복사)가 있으면 자동으로 그 단계에 붙습니다. 하나로 정하지 못한 시간은 '확인 필요'에서 개발자가 배정합니다. 대화 원문은 저장하지 않고, 코드처럼 생긴 토큰(하이픈·숫자 포함)만 후보로 남깁니다.

### 단계마다 새 세션 (한 세션 = 한 요구사항 × 한 단계)

"알아서 만들어 줘" 한 번이면 분석·설계·개발이 한 세션에 섞여 단계별 효과를 잴 수 없으므로, 단계마다 세션을 새로 열고 단계 사이는 산출 문서로 잇습니다. 공수 입력 화면 단계 줄의 **지시문** 버튼이 첫 메시지를 만들어 줍니다(`src/lib/measure/stageGuide.ts`).

| 단계 | 시킬 일 | 읽을 문서 | 남길 문서 (`docs/poc/<과제ID-요구사항ID>/`) |
|---|---|---|---|
| 분석 AN | 요구사항·현행 소스·데이터 분석 (설계·코드 금지) | — | `01_분석.md` |
| 설계 DS | 화면·테이블·인터페이스·흐름 설계 (코드 금지) | `01_분석.md` | `02_설계.md` |
| 개발 DV | 설계대로 구현 + 단위 테스트 | `02_설계.md` | `03_개발.md` |
| 테스트 TS | 테스트 케이스 작성·실행, 결함 조치 | 01~03 | `04_테스트.md` |

파일 이름에 단계 코드를 넣지 않습니다 — 다음 단계 세션에서 경로를 말할 때 단계 코드가 둘이 되면 미분류로 빠집니다. 한 세션에 단계 코드가 여럿이면 미분류로 남고 공수 모니터링의 '한 세션에 여러 단계'로 잡힙니다.

### 세션 파일 올리기

Codex 는 OpenTelemetry 로 포털에 바로 보낼 수 없어서, 개발자가 PC 의 Codex 세션 파일을 **공수 입력 > Codex 기록 올리기**로 올립니다.

- 파일 위치: `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` (Windows `%USERPROFILE%\.codex\sessions`, `CODEX_HOME` 이 있으면 그 아래). 파일 몇 개만 고르거나 `sessions` 폴더를 통째로 골라도 됩니다.
- **브라우저가 파일을 읽어** 세션 × 일자(KST)별 활동 시간·모델별 토큰·공수 태그 후보만 뽑아 보냅니다. 대화 원문은 서버로 가지 않습니다.
- 활동 시간 = 기록 사이 간격의 합(5분 넘게 비면 5분까지만). 토큰 = `token_count` 누적값의 증가분을 `turn_context` 모델별로. 자정을 넘긴 세션은 날짜별로 나눕니다. 측정 시작일 이전 날짜는 빠집니다.
- 올린 사람 계정으로 저장됩니다. 같은 세션을 다시 올리면 시간·토큰만 갱신되고 배정·업무 외 처리 결과는 유지됩니다.
- 개발자별 마지막 올린 시각은 시스템 관리 > 수집 현황에서 봅니다.

## 지표 (모두 확정된 날만, 산식 원본은 엑셀 '05. 주요 집계 로직')

| 구분 | 지표 | 산식 |
|---|---|---|
| 주요 | 투입 공수 절감률 | 1 − Σ실제 투입(분) ÷ Σ(기준 공수(M/D) × 480) |
| 주요 | 절감 공수 (M/D) | Σ(기준 공수(분) − 실제 투입(분)) ÷ 480 |
| 주요 | 비용 순절감률 | (Σ기준 인건비 − Σ실제 인건비 − ΣAI 비용) ÷ Σ기준 인건비 |
| 주요 | 비용 순절감액 (원) | Σ기준 인건비 − Σ실제 인건비 − ΣAI 비용 |
| 보조 · 활용 | AI 활용률 | ΣAI 내 투입 ÷ Σ실제 투입 |
| 보조 · 활용 | AI 밖 비중 | ΣAI 밖 투입 ÷ Σ실제 투입 |
| 보조 · 관리 | 태그 입력률 | 태그로 자동 배정된 시간 ÷ 수집된 AI 시간 전체 |
| 보조 · 관리 | 다음 날 확정률 | 다음 영업일 23:59 까지 처음 확정한 (사번·일자) ÷ 기록이 있는 (사번·일자) |

- 480 = 1 M/D 분(설정, 기본 8시간). 인건비 = M/D × 단계의 필요 개발자 등급 M/D 단가.
- AI 비용 = (입력 − 캐시) × 입력 단가 + 캐시 × 캐시 단가 + 출력 × 출력 단가. 토큰이 없거나 단가표에 없는 모델이면 **빈칸**(합계에는 0, 화면에 건수 표시).
- 확정 뒤 수집값이 늦게 들어와 값이 달라지면 '다시 확정 필요'가 되고 다시 확정할 때까지 집계에서 빠집니다.
