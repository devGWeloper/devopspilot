## 1. 단계 4개로 축소 · 운영 기능 전부 제거

운영 과제는 PoC 에 없다(사용자 확인). 운영을 고려한 기능은 남기지 않는다.

- `StageCd = "AN" | "DS" | "DV" | "TS"`, `STAGES`·`STAGE_LABEL` 에서 DP·OP 제거. 설정 `workTypes` 도 DP·OP 키 삭제.
- **과제 구분(개발/운영) 항목 삭제**: `PrjKind`·`PRJ_KINDS`·`Project.kind` 제거. 따라 지울 곳:
  - `/` 과제 현황 '개발·운영' 필터, 과제 칩 · `/dashboard`·`/dashboard/basis` `kind` 필터·쿼리 · 과제별 카드 부제
  - `/master` 과제 표 '구분' 열·과제 편집 대화상자 · `projects/service.ts` 구분 검사
  - `lib/dims.ts` '과제 구분' 축 · `projects/form.ts` PRJ-13 · `normalize.ts` 기본값
  - 엑셀 '01. 과제' 구분 열: 내려받기에서 빼고, 올리기는 열이 있어도 무시(이미 배포된 양식 호환)
- 작업 유형 A6 '환경·배포·운영 조치' → **'환경·배포 조치'**(설명에서 운영 문구 제거). 측정 시작 전이라 의미 변경 문제 없음.
- 엑셀 올리기: 단계 값이 AN·DS·DV·TS(또는 분석·설계·개발·테스트)가 아니면 오류 — 기존 원칙대로 한 건이라도 틀리면 저장 안 함.
- 저장된 DP·OP 태그·`kind` 값(측정 시작 전 샘플뿐)은 읽을 때 버린다. 샘플 데이터에서 운영 과제(MES 운영 개선 요청·물류 운영 SR 처리)와 OP·DP 태그를 지우고 개발 과제로만 다시 만든다.
- 테스트의 OP·운영 픽스처 정리(`match`·`monitor`·`project-workbook`).
- 단위 코드 형식 `과제ID-요구사항ID-단계` 는 그대로(단계 자리 값만 4개).
- 손대지 않음: '운영 DB'·'운영 환경' 같은 서비스 운영(배포 환경) 뜻의 주석·README 문구.

## 2. 개발자 공수 입력 화면 `/effort`

기존 사이드바·컴포넌트(Panel·Chip·Button·표)로, 무채색. 색은 '확정 필요'·'확인 필요' 경고에만.

```
┌ 왼쪽 ─────────────────┐ ┌ 오른쪽: 선택한 요구사항 ─────────────────────────────┐
│ 과제 [전체 ▾]          │ │ 설비 이벤트 수신 로직 변경  DAE01-REQ0047   측정 중   │
│ ☐확정 필요 2 ☐측정 중 2 │ │ ┌분석────┐┌설계────┐┌개발────┐┌테스트──┐          │
│ ⚠ 확인 필요 AI 4건 2.8h │ │ │완료     ││대상 아님││진행 중  ││진행 중  │          │
│ ─────────────────────  │ │ │박개발   ││        ││4.2/5.5 ││0.3/1.5 │ M/D      │
│ ▣ REQ0047 확정 필요 2일 │ │ └────────┘└────────┘└────────┘└────────┘          │
│ ☐ REQ0051 확정 필요 2일 │ │ 세션 시작 시 입력: [poc DAE01-REQ0047-DV 복사] [..TS] │
│                        │ │ 일자     │분석│설계│ 개발        │ 테스트     │합계│확정│
│                        │ │ 확정합계 │ ·  │ ·  │ 27.8        │ 0.0        │27.8│    │
│                        │ │ 11/12목  │ ·  │ ·  │AI[3.2]＋외1.0│AI 0 ＋외   │4.2 │[확정]│
│                        │ │ ▸ 확정된 날 7일 · ＋기록 없는 날 추가 · 모두 확정    │
└────────────────────────┘ └──────────────────────────────────────────────────────┘
```

- **왼쪽 = 내 담당 요구사항 목록**(과제 필터, 확정 필요/측정 중/완료 체크, 확인 필요 AI 세션 진입). 체크로 여러 요구사항을 함께 펼친다.
- **단계 띠**: 4칸 고정. 태그 없음 = '측정 대상 아님', 남의 태그 = 담당자 이름만, 내 태그 = 상태·업무 유형·투입/기준 M/D. 개발자도 자기 진행 정도를 보는 용도라 기준 M/D 는 여기만 보이고, 절감률 같은 비교 숫자는 띄우지 않는다.
- **일자 × 단계 표**: 내 태그가 있는 단계만 입력 칸, 나머지는 `·`. 칸 = AI 도구 내(수집값 이하로 줄이기만) + `＋외` 버튼(기존 작업 유형 8개 대화상자 그대로). 행 끝에 일자 합계·확정 버튼.
- 확정은 지금처럼 저장은 (개발자 × 요구사항 × 일자), 버튼은 행 단위. "확정 필요 n일 모두 확정" 은 기존 `confirmDays(reqId)` 를 그대로 쓴다.
- 확정된 날은 접고 '확정 합계' 행만 보인다. "기록 없는 날 추가" 는 기존 `addExtraDay`.
- 오늘 날짜: AI 수집이 실시간(텔레메트리)이면 그대로 보여 주고, 업로드만 쓰는 사람은 '수집 전' 표시.
- 지금의 날짜 중심 보기는 없앤다(두 보기를 유지할 만큼 기간이 길지 않음). 관리자·열람자는 개발자 선택 후 같은 화면을 조회 전용으로.

## 3. 세션 단계 코드 (Codex 텔레메트리·`.codex` 로그)

개발자에게 **세션을 시작할 때 첫 프롬프트에 단계 코드를 넣도록** 안내한다. 수집 쪽은 `measure-base-data` 대로 프롬프트에서 코드처럼 생긴 토큰만 hints 로 남기고 원문은 버린다(불변 규칙 6).

- 받는 형식(위가 우선):
  1. 태그 전체 `DAE01-REQ0047-DV` — 화면의 `poc …` 복사 버튼이 주는 값
  2. 요구사항 ID + 단계 `REQ0047-DV` — 내 담당 중 하나로 정해질 때만. **추가 규칙**: `matchSession` 에 `reqId-단계` 정확 일치 단계를 넣는다(지금은 태그 전체·reqKey·reqId 만 봄)
  3. 요구사항만 `REQ0047` — 그 요구사항에 내 단계가 하나뿐일 때만 자동, 여럿이면 '확인 필요'
- `poc off` = 업무 외 사용. 숫자가 없어 지금 hints 추출에 안 걸리므로 수집 스크립트·OTLP 파서에서 `poc off` 를 `OFF` 힌트로 따로 남기고, 매칭에서 OFF 면 업무 외로 처리.
- 한 세션에 코드가 여러 개면 지금처럼 자동 배정하지 않고 '확인 필요'에서 고르게 한다(세션 중간에 단계를 바꾸는 경우).
- `/guide` 에 "세션마다 첫 줄에 `poc 태그`" 를 가장 위에 둔다.

## 4. 기준 공수 — 요구사항 × 단계로 입력 (관리자)

- `measure-base-data` 의 `/master` '공수 태그' 탭 기본 보기를 **요구사항 행 × 분석·설계·개발·테스트 열** 격자로 한다. 칸 = 기준 공수(M/D)·담당, '—' = 그 단계 태그 없음(측정 대상 아님). 행을 누르면 기존 요구사항 대화상자에서 단계·기준 공수·담당을 고친다(구현: 칸 직접 입력 대신 — 과제 단위 낙관적 잠금이라 연속 입력 시 충돌이 나기 쉬움).
- 엑셀 '02. 요구사항-SDLC' 는 지금처럼 태그 1행(단계 1개) — 격자는 화면 편집 방식일 뿐 저장 모양은 같다.
- 기준 공수 변경은 측정 중인 태그면 사유 필수 + 변경 이력(목업 규칙).
