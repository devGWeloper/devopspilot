## 1. 데이터 모델 — 엑셀 시트 ↔ 포털

| 시트 | 포털 |
|---|---|
| 01. 과제 | `Project` — **과제 ID 를 엑셀 값 그대로**(예 `DAE01`, 자동 PRJ-0001 폐지). 추가: PROMIS 코드, SK AX 소속 본부. 제거: 기존 WBS 실적 |
| 02. 요구사항-SDLC | 행 1개 = **공수 태그** = `과제ID-요구사항ID-단계` (`DAE01-REQ0047-DV`). 난이도·필요 등급·기준 공수·공수 출처·측정 상태·측정 완료일·예상 기대효과·명세 명확성·맥락 주입 가능성·생성 패턴을 **태그(단계) 단위**로 가진다 |

| 03. 개발자 권한 관리 | 계정: 사번 = 로그인 ID, 성명, SK AX 본부·팀, 권한(개발자/관리자), **AI 도구 계정(oTel 계정 Key)** |
| 04. 기준정보 | 등급 단가(원/MM 참고, **원/MD 계산용**), **토큰 단가 표**(모델별 입력·캐시 입력·출력 원/1M 토큰) |
| 05. 주요 집계 로직 | 지표 8개 정의 — 코드(`metrics.ts` 의 지표 정의 목록)가 원본, 화면·엑셀 내보내기가 같은 문구를 쓴다 |

- 요구사항 ID 는 **과제 안에서만 유일**. 내부 식별은 `reqKey = 과제ID-요구사항ID`, 단위 코드 = `reqKey-단계` (CLAUDE.md 불변 규칙 2 문구를 이 형식으로 갱신).
- 요구사항 = 같은 reqKey 를 가진 태그 묶음. 요구사항명은 시트에 없으므로 선택 항목(비면 요구사항 ID 표시).
- 측정 상태: `완료`(관리자 지정, 측정 완료일) 만 저장하고 `측정 중`/`대기` 는 계산. 요구사항 상태 = 모든 태그 완료면 완료.
- 업무 유형(`workType`)은 시트에 없지만 화면 편집용으로 유지(선택).
- 기존 저장 데이터(요구사항 단위 등급 등)는 읽을 때 태그로 내려 채운다(측정 시작 전이라 가볍게).

## 2. 지표 (`measure/metrics.ts` 에만)

1 M/D = `mdHours`(설정, 기본 8h = 480분). 모두 확정된 날만.

| 구분 | 지표 | 산식 |
|---|---|---|
| 주요 | 투입 공수 절감률 | 1 − Σ실제 투입 ÷ Σ기준 공수 (기존 save) |
| 주요 | 절감 공수 (M/D) | Σ기준 M/D − Σ실제 M/D **(신규)** |
| 주요 | 비용 순절감률 | (Σ기준 인건비 − Σ실제 인건비 − ΣAI 비용) ÷ Σ기준 인건비 (기존 net) |
| 주요 | 비용 순절감액 (원) | Σ기준 인건비 − Σ실제 인건비 − ΣAI 비용 **(신규)** |
| 보조·활용 | AI 활용률 | ΣAI 내 ÷ Σ실제 투입 (기존 use) |
| 보조·활용 | AI 밖 비중 | ΣAI 밖 ÷ Σ실제 투입 **(신규)** |
| 보조·관리 | 태그 입력률 | 태그로 자동 배정된 AI 시간 ÷ 수집된 AI 시간 전체(미배정·업무 외 포함) **(신규)** — 직접 배정은 '태그 붙인 시간'이 아님 |
| 보조·관리 | 다음 날 확정률 | 다음 영업일 안에 확정한 (사번·일자) ÷ 기록이 있는 (사번·일자) **(신규)** — 판정은 **첫 확정 시각** 기준(재확정해도 늦어지지 않게 `firstConfirmedAt` 추가) |

- 인건비 = M/D × **태그의 필요 개발자 등급** MD 단가.
- AI 비용 = Σ 토큰 × 모델 단가. 세션을 나눠 배정하면 토큰 비용도 분 비율로 나눈다. 토큰 정보가 없거나 단가표에 없는 모델은 **비용 빈칸**(합계에 0, 화면에 '토큰 단가 미입력 n건' 표시). 기존 도구별 시간당 비용은 폐지.

## 3. Codex 수집

- **텔레메트리**: Codex `~/.codex/config.toml` 의 `[otel]` 로그 이벤트(OTLP/HTTP JSON) → `/api/otel/v1/logs`. Codex 는 활동 시간 메트릭이 없으므로 **이벤트 간격(5분 이내만)을 더해 활동 시간**을 만든다(로컬 스크립트와 같은 규칙). 세션 행에 마지막 이벤트 시각을 둬 다음 묶음과 이어 계산.
  - 토큰: `codex.sse_event`(response.completed)의 input/cached/output 토큰 + `model`.
  - 태그 후보: `codex.user_prompt` 의 프롬프트(`log_user_prompt = true`)에서 코드처럼 생긴 토큰만, 원문은 버림.
  - 사용자: 이벤트의 `user.email`/`user.account_id` 를 계정의 **AI 도구 계정** 과 맞춤 → 없으면 기존 규칙.
  - `/api/otel/v1/metrics`(Claude Code 전용)·Claude 파서 제거.
- **로컬 로그**: `collect_ai_usage.py` 는 Codex `~/.codex/sessions/**/rollout-*.jsonl` 만 읽고, 일자별 모델별 토큰(`token_count` 이벤트의 last_token_usage, `turn_context.model`)을 함께 담는다.
- **태그 추출**: 형식을 가정하지 않고 하이픈과 숫자가 든 토큰(`DAE01-REQ0047-DV`, `REQ0047` 류)을 후보로 모으고, 포털이 현재 태그와 맞춘다: 태그 정확 일치 → reqKey 일치(내 담당 1개) → 요구사항 ID 단독(내 담당 중 유일할 때만).

## 4. 화면

- **신규 `/master` 기준 데이터** (관리자, 사이드바 '관리' 그룹): 탭 `과제 · 공수 태그 · 개발자 · 기준정보 · 집계 로직` + **엑셀 올리기/내려받기**(위 5개 시트와 같은 형식, 빈 데이터면 양식).
  - 과제: 표 + 추가/수정/삭제. 공수 태그: 과제·요구사항별 태그 표, 담당 사번·등급·기준 공수 등 편집, 측정 완료 지정. 개발자: 기존 계정 관리에 본부·팀·AI 도구 계정 추가. 기준정보: 등급 단가(MM·MD)·토큰 단가·1 M/D 시간·측정 시작일·업무 유형. 집계 로직: 지표 정의 표(읽기 전용).
  - 엑셀 올리기: 전부 검사 후 오류가 하나라도 있으면 저장 안 함(기존 원칙). 파일에 있는 행은 파일 값으로 갱신, 없는 행은 유지(삭제는 화면에서). 새 사번은 계정을 만들고 **초기 비밀번호를 결과 창에 한 번만** 보여 준다.
- `/` 과제 현황: 조회 전용으로(편집·엑셀 버튼은 `/master` 로 이동). 태그 코드 표시.
- `/admin`: 확정 현황(다음 날 확정률 열 추가) · 수집 현황(토큰·비용 열) · 변경 이력. 계정·코드·단가 탭은 `/master` 로 이동.
- `/dashboard`: 지표 카드 8개(주요 4 · 보조 4), 산출 근거에 토큰·비용 근거. 성격별 결과·`/selection` 분포는 태그 단위 축(난이도·등급·기대효과·명세·맥락·생성 패턴 = 상/중/하, 단계, 과제 속성). 선정 양식 v0.0 전용 항목(AI 적용 계획·참여 인력)과 v0.0 엑셀 올리기는 제거.
- `/guide`: Codex 설정(config.toml), 브랜치·프롬프트에 태그 적는 법.
